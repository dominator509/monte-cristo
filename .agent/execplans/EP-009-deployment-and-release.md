# EP-009 -- Deployment and release

## 1. Purpose / Big Picture

Produce the artifact set and prove it. Three platform tarballs with a checksum manifest, a
cross-platform determinism drill in which each shipped binary replays the golden tape and
must reach the hash recorded on Linux, a save-migration check against every previously
shipped schema fixture, and a rollback drill that is actually performed rather than described.

## 2. Scope

Release build configuration, artifact staging, `SHA256SUMS`, the third-party licence file,
the cross-target determinism drill, the migration check, and the rollback drill.

## 3. Non-goals

No publishing. Auto-Deploy Authorization is `no`; the MANUAL publish command is emitted in
EP-010 and executed by a human. No new features, no content changes, no gate changes.

## 4. Context and Orientation

DEPLOYMENT.md and RELEASE.md are authoritative. The cross-target determinism drill is the
part that matters: it is the only place the cross-platform half of LF-09 is actually proven,
and a mismatch on any target fails this node rather than being deferred.

## 5. Files to Read First

- DEPLOYMENT.md in full
- RELEASE.md in full
- ROLLBACK.md sections 3, 8, 11
- ASSUMPTIONS.md A-06, A-09

## 6. Expected Changed Files

- scripts/build.sh
- CHANGELOG.md

- crates/mc_shell/src/main.rs

## 7. Interfaces and Contracts

Artifact naming is `monte-cristo-<version>-<target-triple>.tar.gz` exactly, with `SHA256SUMS`
covering the set, staged into `$MC_ARTIFACT_DIR`. Target triples are
`x86_64-unknown-linux-gnu`, `x86_64-pc-windows-gnu`, and `aarch64-apple-darwin`. Tarball
contents are exactly the list in DEPLOYMENT.md section 3. The shipped binary exposes
`--version`, `--verify-content`, `--check-paths`, `--save-info <file>`, and
`--replay <tape> [--assert-hash]`, each of which runs without opening a window. The hash of
record for the cross-target drill is the Linux value in `tapes/HASHES.txt`.

### M3: Artifact staging and manifest

### M4: Cross-target determinism drill
GOAL: Every shipped binary replays the golden tape to the hash recorded on Linux.
READ: TESTING.md section 6 item 4, ASSUMPTIONS.md A-09
CHANGE: (none -- this milestone produces evidence, not files)
CONTENT: for each tarball, extract into a clean temporary directory and run the shipped
  binary's replay against `tapes/golden-full.tape`, comparing to the hash in
  `tapes/HASHES.txt`.
RUN:
  for t in "$MC_ARTIFACT_DIR"/monte-cristo-*.tar.gz; do d=$(mktemp -d); tar xzf "$t" -C "$d"; MC_HEADLESS=1 "$d"/monte-cristo --replay tapes/golden-full.tape --assert-hash; rm -rf "$d"; done
EXPECT: `hash: match` once per artifact, with no `hash: mismatch` anywhere
EVIDENCE: sh scripts/ledger.sh append <AGENT_ID> EP-009 MILESTONE_PASS "M4 cross-target hashes match"
FALLBACK: none needed. A mismatch is an INV-01 defect and is fixed at its source; it is never
  waived here, because cross-platform determinism is a ship criterion.
COMMIT: git add -A && git commit -m "[EP-009][M4] record cross-target determinism drill evidence"

### M5: Migration check and rollback drill
GOAL: Old saves migrate, and a rollback is performed for real.
READ: DEPLOYMENT.md sections 6, 7, ROLLBACK.md section 11
CHANGE: (none -- evidence is recorded in Progress)
CONTENT: run the migration check against every committed fixture save. Then perform the drill:
  stage version N and N+1 into a temporary publish tree, deliberately corrupt N+1, detect it
  with the section 8 verification, execute the ROLLBACK.md section 3 commands against the
  temporary tree, and re-verify. Record the commands and outputs in Progress.
RUN:
  cargo run --locked -p mc_tools -- save-migrate --dir tests/fixtures/saves-v1 --dry-run
  sh scripts/smoke-test.sh
EXPECT: the migration reports every fixture migrating cleanly; `smoke test: ok`
EVIDENCE: sh scripts/ledger.sh append <AGENT_ID> EP-009 MILESTONE_PASS "M5 migration ok, rollback drill performed"
FALLBACK: none needed. A drill that was not actually performed does not count and must not be
  recorded as done.
COMMIT: git add -A && git commit -m "[EP-009][M5] verify save migration and perform rollback drill"

## 10. Idempotence and Recovery

version tag is created in EP-010, not here, so nothing in this node is irreversible. To
re-enter cold: read Progress, find the first unchecked milestone, re-run the previous
milestone's RUN, continue.
